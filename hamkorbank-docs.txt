Схема по процессу взаимодействия

Данное руководство предназначено для разработчиков, выполняющих интеграцию с API Internet Acquiring.

Для работы с API доступны две среды:

Тестовая – используется для разработки и тестирования.
Продуктивная – используется для проведения реальных операций.

Адреса API, а также данные для авторизации предоставляются отдельно.

Формат взаимодействия с API

Обмен данными с API осуществляется посредством HTTP-запросов в формате JSON.

Каждый запрос должен содержать следующие обязательные элементы.

HTTP-заголовки (Headers)
Content-Type – application/json; charset=utf-8
Accept – application/json
Тело запроса (Body)

Тело запроса передаётся в формате JSON и содержит следующие параметры:

method – название вызываемого метода API.
params – параметры, необходимые для выполнения метода.

Для обеспечения безопасности API реализована двухступенчатая авторизация:

Two-Way SSL (отправка клиентского сертификата при вызовах)
OAuth2 (Bearer Token)
Инструкция по созданию и использованию сертификата

Сертификат выдаётся клиенту Банком. Для получения сертификата пользователь должен предоставить CSR файл Банку.

При создании используются команды openssl через командную строку.

Создание Private_key организации пользователя (этот *.key должен храниться у пользователя, этот ключ нужен только для сервисов пользователя, банку он не предоставляется!)

openssl genrsa -des3 -out user1.key 4096

Создание сертификата организации пользователя с использованием Private_key (этот сгенерированный сертификат *.csr предоставляется сотрудникам банка)

openssl req -new -key user1.key -out user1.csr

Созданный CSR файл предоставляется Банку. Банк, основываясь на этом файле, создаёт сертификат и предоставляет его пользователю.

Банк вводит сертификат пользователя на сервер банка на основании лимита на 1 год работы в сервисах банка и предоставляет пользователю сертификат в виде *.crt — этот сертификат необходимо продлевать ежегодно!

Сертификат, предоставленный банком (*.crt), используется в конвертации (*.pfx, *.p12, ...) или в своём виде (*.key и *.crt) в зависимости от потребностей технологии (программного обеспечения), используемой пользователем (организацией).

Конвертация .crt файла в pfx:

openssl pkcs12 -export -out output.pfx -inkey private.key -in fullchain.crt

Важные замечания

Callbacks или «колбеки» являются неотъемлемой частью взаимодействия нашего API с вашим сервером. Они позволяют вашему сервису получать уведомления о различных событиях и реагировать на них в реальном времени.

Ваш сервер должен обработать полученный колбек запрос и вернуть статус 200 OK. Это подтверждает нашему серверу, что уведомление было получено и обработано.

При создании платежной ссылки (инвойса)
Для работы с callback необходимо предварительно получить key и secret у администраторов.

  "signature": "865CA1F6E2EC7E3C11666967C91FF4FADF4BD7D0",
  "ext_id": "ext-test-1234567",
  "state": 2,

Алгоритм хеширования CalculateHash

Данная функция вычисляет двухэтапный SHA3-256 хеш на основе входного UUID с использованием фиксированных префикса и секрета.

Входные данные

externalID — строка, содержащая то, что было передано в pay.create.url (например, ext-test-1234567)

Выходные данные

Строка в верхнем регистре, содержащая 64-символьный шестнадцатеричный SHA3-256 хеш.

Константы
prefix	"key"
secret	"secret"
Алгоритм (пошагово)

Этап 1 — первый хеш:

firstHashInput = prefix + secret + externalID
firstHash = SHA3-256(firstHashInput)
firstHashUpper = TO_UPPERCASE(firstHash)

Этап 2 — второй хеш:

secondHashInput = firstHashUpper + externalID
finalHash = SHA3-256(secondHashInput)
result = TO_UPPERCASE(finalHash)
Псевдокод
function CalculateHash(externalID: string) -> string:
    prefix = "key"
    secret = "secret"

    # Этап 1
    firstInput = prefix + secret + externalID
    firstHash = sha3_256(firstInput)
    firstHashUpper = uppercase(firstHash)

    # Этап 2
    secondInput = firstHashUpper + externalID
    finalHash = sha3_256(secondInput)
    return uppercase(finalHash)
Пример ввода/вывода
Вход	externalID = "ext-test-1234567"
prefix = "key"
secret = "secret"
Выход	865CA1F6E2EC7E3C11666967C91FF4FADF4BD7D0
Примеры реализации
Python
import hashlib


def sha3_hash(text):
    return hashlib.sha3_256(text.encode('utf-8')).hexdigest()


def calculate_hash(externalID):
    prefix = "key"
    secret = "secret"

    first_input = prefix + secret + externalID
    first_hash = sha3_hash(first_input).upper()

    second_input = first_hash + externalID
    final_hash = sha3_hash(second_input).upper()

    return final_hash
JavaScript (Node.js)
const crypto = require('crypto');

function sha3Hash(text) {
    return crypto.createHash('sha3-256').update(text).digest('hex');
}

function calculateHash(externalID) {
    const prefix = "key";
    const secret = "secret";

    const firstInput = prefix + secret + externalID;
    const firstHash = sha3Hash(firstInput).toUpperCase();

    const secondInput = firstHash + externalID;
    return sha3Hash(secondInput).toUpperCase();
}
Go
func CalculateHash(externalID string) string {
    const prefix = "key"
    const secret = "secret"

    firstHashInput := prefix + secret + externalID
    firstHash := strings.ToUpper(sha3Hash(firstHashInput))

    secondHashInput := firstHash + externalID
    return strings.ToUpper(sha3Hash(secondHashInput))
}

func sha3Hash(input string) string {
    hasher := sha3.New256()
    _, err := hasher.Write([]byte(input))
    if err != nil {
        log.Printf("encode error: %v", err)
        return ""
    }
    hashBytes := hasher.Sum(nil)
    return hex.EncodeToString(hashBytes)
}
Важные замечания
Все строки — UTF-8.
Все хеши — в верхнем регистре (A–F, не a–f).
Конкатенация строк — без разделителей.

О Hamkor Payment SDK

Hamkor Payment SDK — это библиотека для интеграции платёжной системы Hamkorbank в веб- и мобильные приложения на базе JavaScript/TypeScript- фреймворков для приложений на базе Ionic.

Возможности SDK
Приём платежей с карт HUMO и UZCARD
SMS OTP подтверждение платежей
Поддержка фискализации чеков
Настраиваемый логотип мерчанта
Все операции с чувствительными платёжными данными выполняются на стороне Банка. Это обеспечивает высокий уровень безопасности персональных данных, поскольку партнёр не получает и не обрабатывает данные банковских карт.

Использование SDK позволяет реализовать удобный и безопасный сценарий оплаты без перенаправления пользователя во внешний браузер, улучшая пользовательский опыт.

Ключи и доступы

Банк предоставляет партнёру следующие ключи для интеграции:

key / secret	Секретный ключ, используемый для авторизации серверных (backend) запросов при получении payment_token. Передаётся по защищённому каналу и должен храниться исключительно на стороне партнёра с соблюдением требований безопасности.
public_key	Публичный ключ, используемый партнёром при взаимодействии с мобильным SDK для инициации платёжных операций.
